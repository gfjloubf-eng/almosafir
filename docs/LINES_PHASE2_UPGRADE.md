# دليل ترقية المرحلة 2 — شبكة الخطوط الرسمية (للمالك فقط)

> ⚠️ **هذه الخطوة الوحيدة التي تغيّر مخطط قاعدة البيانات في المشروع حتى الآن.**
> التغيير **إضافي محض**: ينشئ 3 جداول جديدة فقط ولا يلمس أي جدول أو صفّ قائم.
> التطبيق لا يشغّل الترقيات تلقائياً عند الإقلاع — لن يتغير شيء في قاعدتك حتى تنفّذ الأمر بنفسك.

## الخطوات (مرة واحدة، بعد سحب آخر main ‏ `git pull`)

1. **انسخ قاعدتك احتياطياً** (وقاية معتادة قبل أي ترقية):
   ```bash
   "C:\xampp\mysql\bin\mysqldump.exe" -u root mosafir_db > backup_before_lines_%DATE%.sql
   ```
   *(إن كان mysql.exe معطوباً لديك كما سابقاً: من phpMyAdmin ← قاعدة mosafir_db ← Export ← Go.)*

2. **طبّق الهجرة** من مجلد المشروع:
   ```bash
   dotnet ef database update
   ```
   متوقع (منسق اعتيادي):
   ```
   Applying migration '20260831200000_Phase2_RouteLines'.
   Done.
   ```

3. **تحقّق** من phpMyAdmin: ظهرت الجداول `route_lines`, `line_stops`, `line_schedules` ✔
   ثم شغّل: `dotnet run --project src/AlMosafer.Web` وافتح «شبكة الخطوط 🛣️» في القائمة.

4. **من لوحة الإدارة** («الخطوط 🛣️»): أنشئ أول خط، أضف مواقفه مرتبة، ثم مواعيده الأسبوعية.

## التراجع (إن لزم)
```bash
dotnet ef database update 20260828154624_InitialCreate
```
يحذف الجداول الثلاثة فقط ويبقي كل بياناتك.

## ملاحظة صدق مزدوجة
- كتبتُ الهجرة يدوياً بنسق `InitialCreate` حرفياً، ولم يتسنَّ لي تجربتها في هذه البيئة (بلا .NET SDK وبلا وصول لقاعدتك) — لذا النسخة الاحتياطية في الخطوة 1 إلزامية، وCI يجزم بصحة **الترجمة والاختبارات فقط** لا بتطبيق الهجرة على MySQL حقيقي.
- لقطة النموذج (`AlMosaferDbContextModelSnapshot`) حُدّثت يدوياً بنفس النمط؛ إن أظهر `dotnet ef migrations add` مستقبلاً فرقاً غير مقصود، أخبرني وأصلحه فوراً.
